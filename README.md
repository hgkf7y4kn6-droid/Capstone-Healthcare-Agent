# Tendwell AA

*AA stands for Administrative Assistant.* **The front desk that never closes.** Tendwell AA answers patients, routes refills through clinical safety rules and takes booking requests around the clock. Clear-cut requests finish on their own; everything else waits for the right person with the context already gathered.

It grew out of an agentic healthcare-assistant capstone (EHR, scheduling, prescription refills, support triage) and is now a product: a branded web app for clinic staff and patients on top of the same rule engines and agents.

## How a request is handled

1. **Safety screen** (`workflows/safety.py`) — fixed rules catch emergencies (chest pain, stroke signs, breathing trouble, self-harm, overdose…) and answer with 911/988/Poison Control before anything else runs. No model ever decides whether something is an emergency.
2. **Rules** — refills pass identity verification, controlled-substance, refill-count and lab-range gates (`workflows/prescription_refill.py`); support messages are triaged (`workflows/feedback_support.py`). A failed rule routes to a provider with the chart context pre-assembled.
3. **Language** — the assistant explains. `ASSISTANT_ENGINE=crew` uses the CrewAI planner + executor on a local Qwen model; `concierge` (the hosted default) answers deterministically over verified records and MedlinePlus; `auto` uses CrewAI when installed and falls back to the concierge on any failure.

## Run it locally

```bash
pip install -r requirements.txt          # add requirements-ai.txt for CrewAI + local model + Streamlit
uvicorn api.app:app --reload --port 8000 # API; loads synthetic demo patients on first start

cd web && npm install && npm run dev     # web app on http://localhost:5173 (proxies /api)
```

Sign in with the demo access code shown on the sign-in page (`tendwell-demo` in development). From a patient's page, **Open their portal** to try the patient experience.

To serve everything from one process, `cd web && npm run build` and the API serves `web/dist` at `/`.

## Tests

```bash
python -m unittest discover -s tests     # 146 tests, no network or model needed
cd web && npm test && npm run lint && npm run build
```

`web/tests/tokens.test.mjs` keeps the CSS theme in sync with `web/src/tokens.ts` and enforces contrast minimums in light and dark.

## Deploy (Render)

`render.yaml` defines one Docker web service with a persistent disk. Create it from the Blueprint, set `STAFF_ACCESS_CODE` (and `CORS_ORIGINS` if the web app is hosted elsewhere), then point a subdomain such as `tendwell-aa.richesdigitalventures.com` at it. `SESSION_SECRET` and `PORTAL_JWT_SECRET` are generated by Render.

## Before real patient data

The demo is synthetic. Before a clinic uses Tendwell AA with real patients:

- Turn `DEMO_MODE` off and import the roster with `python -m data.ingest_patient_data --source <export>`.
- Replace the shared access code with per-user sign-in (Clerk or Supabase Auth); routes already depend on `require_staff`, so this is a drop-in.
- Host on infrastructure covered by a signed BAA, move SQLite to managed Postgres, and review log retention — `logs/` records assistant queries.
- Have a provider sign off on the refill rules and the safety-screen wording.

## Layout

```
api/          FastAPI: app.py (product API), staff_auth.py, portal auth + legacy webhook API
agents/       assistant.py (safety → engine), concierge.py, CrewAI crews, local LLM wrapper
workflows/    deterministic rules: safety screen, refills, refill confirmation, support triage
data/         SQLite EHR, ingestion, first-start bootstrap
tools/        CrewAI tool wrappers over workflows
integrations/ MedlinePlus, portal webhook, SQS
evaluation/   LLM-as-judge harness, triage and symptom suites
monitoring/   event log and latency metrics
web/          Vite + React + Tailwind app (design system in docs/design-system.md)
```
